Milestone 2 of 5 on the road to 1.0. See docs/roadmap/README.md for the
protocol rules that govern this handoff.

## Receiving Actor
- Target: AI coding agent or maintainer working in the Forge repository
- Why this target: new specification plus a runner that reuses tested check
  execution code already in src/receipt/acceptance.js
- Expected role: Builder. Specify, then implement, then test, in that order.

- Project: Forge, a framework for governed AI-assisted software construction

  acceptance receipt: real. Gate definition specification: planned. General

  a specified, runnable gate that CI can use
- Build environment: Node 20 or later, zero runtime dependencies, node:test

## Target Outcome
spec/gate-definition.md defines a JSON gate file. src/gate/run.js evaluates it
fail closed: a gate passes only when every check it declares ran and exited
zero within its timeout. The repository's own CI runs its baseline through a
gate file, forge.gates.json, using `npm run gate`.

## Non-Negotiable Constraints
- Fail closed: missing, skipped, timed-out, errored, or unparsable checks are
  failures. There is no "warn" outcome.
- Exit codes: 0 means every gate passed, 1 means a gate failed, 2 means
  invalid input or an operational error. These match the receipt CLI.
- Commands are an executable plus an argument array with no implicit shell,
  as in the acceptance receipt contract.
- No new runtime dependencies.

## Preservation Map
- Do not modify: spec/acceptance-receipt.md, receipt JSON format, contract
  binding behavior, handoff validator behavior.
- Preserve: all acceptance receipt tests and harness scenarios unchanged.
- Refactoring shared check-execution code out of src/receipt/acceptance.js
  is allowed only if every existing receipt test passes without edits.

## Required Task Steps
1. Write spec/gate-definition.md with sections Purpose, Gate File, Evaluation,
   Result and Exit Codes, Trust Boundary. Use the metadata block
   (Specification, Version 0.1.0, Status Draft, License) and register it in
   spec/spec-manifest.json.
2. Gate file shape: `{ "schemaVersion": "1.0.0", "gates": [ { "id",
   "description", "checks": [ { "id", "command", "args", "timeoutMs" } ] } ] }`.
   IDs follow the receipt ID pattern.
3. Implement src/gate/run.js with `--file PATH`, optional repeated
   `--gate ID`, and `--json`. Evaluate gates in declared order and all checks
   in each gate (no early exit), so the report is complete.
4. Add an `npm run gate` script, and add forge.gates.json covering the
   baseline commands from the roadmap protocol rules.
5. Add test/gate-run.test.js covering: pass, failing exit, timeout, missing
   executable, empty gate (fails), unknown `--gate` ID (exit 2), malformed
   file (exit 2), duplicate IDs (exit 2).
6. Replace CI's individual baseline steps with `npm run gate`. The steps it
   replaces must all be present in forge.gates.json.
7. Update README usage and CHANGELOG, then release 0.7.0 per protocol rule 5.

## Forbidden Behaviors
- Do not modify or delete failing tests or checks to achieve a passing state.
- Do not add a soft-fail, allow-failure, or retry option.
- Do not invoke a shell implicitly or interpolate strings into commands.
- Do not drop any CI check when moving CI onto the gate runner.

## Output Format
A single pull request with the new spec, runner, tests, gate file, and CI
change, with the Validation Checklist results in its description, including
full `npm run gate` output.

## Validation Checklist
- [ ] `npm run lint:spec` checks 4 specs with 0 violations.
- [ ] `node --test test/gate-run.test.js` passes every listed case.
- [ ] `npm run gate` exits 0 on a clean checkout.
- [ ] Temporarily breaking one baseline check makes `npm run gate` exit 1 and
  name that check. Revert the break before committing.
- [ ] CI on ubuntu-latest and windows-latest runs through `npm run gate` and
  passes.
- [ ] All previously passing tests and harness scenarios still pass.

## Failure Recovery
If blocked: state what blocked completion, separate confirmed facts from
assumptions, leave receipt code and tests untouched, propose the smallest
safe next step, and stop.
